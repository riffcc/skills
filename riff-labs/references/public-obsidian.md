# Public Obsidian

This file is the scaffold for the relationship between the public skill and the public Obsidian vault.

## Current State

The intended public vault path is `~/Obsidian/Riff Public/`.

If that path is not present in the current environment, draft inside a reviewable note in the Riff vault first and promote the page set into the public vault once the wording and boundary are sharp enough.

It may now grow freely, but every page or page set should get at least one review checkpoint on either the intended shape or the actual wording before it lands.

## Role

The public vault is a parallel source, not the primary one in this first pass.

It should expand the public model after the model is sharp enough, not outrun it.

In practice that means the first useful pages should support staff onboarding across the approved product, infrastructure, and storage scope rather than trying to mirror the full internal vault.

## Guardrails

- compress hard
- avoid private lore
- avoid session residue
- prefer reasoning to example cargo cults
- do not copy internal decision chains into public notes
- broad growth is fine if the shape stays reviewable
- keep the public vault aligned to the installed public skill rather than letting the vault invent a wider model first

## First Page Set

The first useful public page set is:

- `Start Here`
- `How We Work`
- `Repo Map`

This set is enough to give staff a landing page, contribution defaults, and a route into the real repositories without pretending the first pass is already a full handbook.

## Second Wave

After the first page set is reviewed, the next pages should expand by family:

- the `riff.cc` stack
- the infrastructure stack
- the storage stack

The first family pages should make `riff.cc`, `Flagship`, `Citadel`, and `Dragonfly` explicit. That order preserves the public face first, then the commercial substrate, then the durability layer that makes the platform real.
